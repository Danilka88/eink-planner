## Что за проект

«Такт» (Takt) — статическое офлайн-приложение: план привычек для 6" e-ink
планшета. Чистый HTML/CSS/JS, ES-модули, без сборщика, без зависимостей, без
сети. Данные — только в `localStorage` устройства.

Живая версия: https://danilka88.github.io/eink-planner/

## Незыблемое

Нарушение любого пункта ломает данные пользователей или обещание приватности.

| Что | Значение | Почему |
|---|---|---|
| Ключ хранилища | `ritual.v1` | смена = потеря всех данных |
| Ключ бэкапа демо | `ritual.backup` | там данные на время демо |
| Ключ битых данных | `ritual.v1.broken` | последний шанс восстановить |
| Адрес сайта и репозитория | `danilka88.github.io/eink-planner` | смена = новое хранилище, установленное приложение слетает |
| Внешние запросы | запрещены, `connect-src 'self'` | обещание «данные не покидают устройство» |
| Палитра | 1-битная, без градиентов и теней | экран e-ink |
| Анимации | нет ни одной | e-ink + энергия |
| Иконки | Phosphor Bold, вшиты в `js/core/icons.js` | CSP запрещает CDN |

## Правила изменений

1. **Новая строка интерфейса** → добавить во все 8 словарей `js/core/dict/*.js`.
   Тест `tests/i18n.test.js` падает, если набор ключей разошёлся.
2. **Новая иконка** → `SOURCE` или `UI` в `js/core/icons.js`; для привычки ещё
   ключ в `HABIT_ICONS` (`js/core/state.js`) и подпись `icon.<ключ>` в 8 словарях.
3. **Изменение модели данных** → миграция в `normalize()`, поднять `VERSION`,
   описать в `docs/DATA-MODEL.md` и `CHANGELOG.md`.
4. **Любая правка** → поднять `APP_VERSION` в `js/core/version.js` **и**
   `version` в `package.json` (тест сверяет). Схема: `MAJOR.MINOR.PATCH`.
   Если менялся `package.json` — обновить и `package-lock.json` (`npm i`).
5. **Изменил файлы оболочки** (`index.html`, `styles.css`, `js/**`) → поднять
   `CACHE` в `sw.js`. Новый модуль в `js/` → добавить его в `SHELL` в `sw.js`;
   `tests/shell.test.js` падает, если импорт не попал в офлайн-кэш. Планшет обновится сам: service worker заметит новый кэш и
   перезагрузит страницу в безопасный момент (см. `docs/ARCHITECTURE.md`).
6. **Новый ресурс** (иконка, шрифт, картинка) → запись в `THIRD-PARTY.md` с
   лицензией. GPL/AGPL в проект не берём.
7. **Новое сетевое поведение** — не добавлять. Вообще.

## Стиль кода

- Ванильный JS, ES-модули, никаких фреймворков и сборщиков.
- Логика, которую можно протестировать, — в `js/core/`, без обращения к DOM.
- Интерфейс — в `js/ui/` по ответственности (см. `docs/ARCHITECTURE.md`), не
  больше 400 строк на файл. Общее изменяемое состояние — только в `store.js`.
- Строки интерфейса — только через `t("ключ")`, никогда литералом в разметке.
- Комментарии — по-русски, по делу; объясняют «почему», а не «что».
- Именование: `camelCase` для переменных, `kebab-case` для файлов, ключи
  словаря — `группа.имя`.

## Что проверять руками (не покрыто тестами)

- Меню «Поделиться» на Android — открывается ли системное окно.
- Офлайн-запуск: авиарежим + перезагрузка ярлыка.
- Поведение e-ink: «призраки» после частых перерисовок.
- Читаемость с 1–2 метров.

## История решений

- Почему `localStorage`, а не IndexedDB: объём данных — килобайты, синхронный
  доступ проще, миграции тривиальны.
- Почему без фреймворка: на e-ink важна предсказуемая перерисовка; 177 DOM-узлов
  и 2 мс на нажатие делают React избыточным.
- Почему CSP в `<meta>`, а не в заголовках: GitHub Pages не даёт управлять
  заголовками.
- Почему тост — строка сетки, а не всплывашка: всплывашка перекрывала плитки и
  давала сдвиг вёрстки (CLS).
