# Архитектура

## Принципы

1. **Без сети.** Ни одного запроса наружу: CSP `connect-src 'none'` запрещает их
   на уровне браузера.
2. **Без сборщика.** ES-модули грузятся как есть, GitHub Pages отдаёт файлы
   напрямую. Нет `node_modules` в рантайме, нет шага сборки.
3. **Без фреймворка.** DOM строится руками, состояние — один объект.
4. **Логика отделена от DOM.** Всё, что можно проверить тестом, лежит в
   `js/core/*` и не трогает `document`.

## Слои

```
js/core/schedule.js   чистая логика: окна, повтор, долги, история
js/core/state.js      модель, миграции, localStorage, демо
js/core/i18n.js       словари, t(), Intl-склонения, даты
js/core/icons.js      SVG-спрайт Phosphor, iconSvg()
js/app.js             DOM, события, рендер, редактор, настройки
js/theme-boot.js      тема до первой отрисовки (без FOUC)
```

Зависимости идут только в одну сторону: `app.js` → `core/*`. Ядро ничего не
знает про интерфейс, поэтому тесты гоняются в Node без jsdom.

## Поток данных

```
localStorage ──load()──► state ──► renderBoard() / renderPanel()
                            ▲                    │
                            └──── persist() ◄────┘  (действие пользователя)
```

- `state` — единственный источник правды, живёт в памяти модуля `app.js`.
- Любое изменение: мутируем `state` → `persist()` → `rerender()`.
- `rerender()` сбрасывает сигнатуру доски, чтобы не перерисовывать DOM зря.

## Почему так, а не иначе

- **Сигнатура доски.** `renderBoard()` сравнивает `id:state:day` всех плиток и
  пересобирает DOM только при реальном изменении. На e-ink лишняя перерисовка —
  это мигание всего экрана.
- **Таймер 15 секунд.** Часы и появление привычки в окне. Работа дешёвая: при
  совпадении минуты ничего не происходит.
- **Диалог `<dialog>`.** Нативный top layer, фокус-трап и Esc бесплатно. При
  входе в полноэкранный режим диалог пересоздаётся — см. `setFullscreen()`.
- **Тост как строка сетки.** Не плавает поверх плиток: он занимает свою строку
  между доской и нижним меню.

## Полноэкранный режим

`requestFullscreen()` на `<html>` вытесняет открытый `<dialog>` из top layer —
окно визуально «проседает». Поэтому `setFullscreen()` сначала закрывает
диалог, запрашивает полный экран и открывает диалог заново после
`fullscreenchange`. Плюс `relayout()` пересчитывает сетку четыре раза, пока
браузер устаканивает вьюпорт.
